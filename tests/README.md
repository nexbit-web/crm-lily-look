# Тести

```bash
npm test           # один прогін
npm run test:watch
npm run test:redis # живий Redis із .env (у npm test пропускається)
```

Усі тести лежать тут, поруч із кодом їх немає. База, мережа й Cloudinary не
потрібні: Prisma підмінюється через `vi.mock('$lib/server/db')`, тому прогін
не залежить ні від `.env`, ні від згенерованого клієнта Prisma.

## Що саме перевіряється

**Безпека**

| Файл                      | Про що                                                               |
| ------------------------- | -------------------------------------------------------------------- |
| `auth-guard.test.ts`      | хук закриває весь CRM; POST без сесії — 401; заголовки безпеки;      |
|                           | понижений чи видалений співробітник втрачає доступ одразу            |
| `sessions.test.ts`        | позначка «перечитати сесію» живе довше за cookie-кеш                 |
| `permissions.test.ts`     | невідома роль дає найменші права                                     |
| `statistics-load.test.ts` | оператор не бачить виручки навіть за прямою адресою                  |
| `api-uploads.test.ts`     | підпис і видалення фото — тільки з сесією, і тільки для своїх файлів |
| `cloudinary.test.ts`      | чужий хост не приймається, api_secret не їде у браузер               |
| `product-input.test.ts`   | форма не пускає в базу чужі посилання й зіпсований JSON              |
| `slug.test.ts`            | в адресу товару не потрапляє нічого, крім латиниці, цифр і дефіса    |
| `admins.test.ts`          | співробітники: лише адмін, себе й останнього адміна не зачепити      |
| `stream-guards.test.ts`   | роль перевіряється до стріму даних — 403 одразу, база не відкрита    |
| `auth-secret.test.ts`     | без BETTER_AUTH_SECRET CRM не стартує з відомим ключем               |

**Навантаження на базу.** Neon відповідає по мережі, тому кожен зайвий запит
коштує затримки. Ці тести ловлять саме повернення старих помилок:

- `product-slug.test.ts` — вільна адреса шукається одним запитом, а не циклом;
- `products-load.test.ts` — чотири запити списку йдуть одним пакетом, сторінка
  береться по 15 товарів, залишок рахується вкладеним `select`;
- `statistics-load.test.ts` — усі вісім запитів сторінки йдуть разом;
- `cache.test.ts` — повторний перегляд береться з Redis одним HTTP-запитом,
  запис у розділі скидає його кеш, збереження посеред читання не лишає в кеші
  старої версії, скидання, що не дійшло, досилається; без Redis або при його
  збої все йде напряму в базу; `auth-guard.test.ts` — збереження скидає кеш
  ще до відповіді;
- `orders-cache.test.ts` — список замовлень із кешу (30 с), кожен фільтр —
  свій запис; зміна статусу спершу скидає кеш, потім будить інші вкладки;
- `db.test.ts` — один клієнт Prisma і один пул зʼєднань на процес, і в
  продакшені теж;
- `redis.live.test.ts` — те саме на справжньому Redis (`npm run test:redis`);
- `options.test.ts`, `categories.test.ts` — підказки й дерево категорій беруться
  одним запитом кожне.

**Надійність даних**

- `money.test.ts` — копійки не втрачаються на числах із плаваючою комою;
- `sizes.test.ts` — порядок розмірів і кирилична «Х» у «4ХL»;
- `product-input.test.ts` — порядок кольорів, звʼязок фото з кольором, заміри;
- `products-load.test.ts` — товар без категорії та фото не ламає сторінку.

**Інтерфейс**

- `skeletons.test.ts` — скелетон кожної таблиці має ту саму сітку колонок,
  що й справжня таблиця; готові дані показуються без скелетона;
- `stream.test.ts` — перше відкриття віддає дані стрімом, переходи — одразу;
- `toast.test.ts`, `post-action.test.ts` — тости й «Скасувати» в них;
- `accent.test.ts` — колір теми лише з переліку, без тексту з cookie;
- `realtime.test.ts` — підписи Pusher, вебхук нового замовлення, доступ до каналу.

**Відвідуваність**

- `traffic.test.ts` — завантажувач: лише SELECT і лише для менеджерів, дані з
  адреси йдуть параметрами, сім запитів одночасно й кожен обмежений періодом,
  київські межі доби (з переходом на зимовий час), кожна цифра з бази доходить
  до відповіді;
- `traffic-page.test.ts` — сама сторінка, відрендерена з даними: плитки,
  воронка, джерела, сторінки, товари, порожні стани, назви з бази не
  виконуються як HTML.

Сторінки рендеряться через `svelte/server`; `$app/navigation` і `$app/state`
підмінені заглушками з `tests/stubs`.

## Як додавати нові

Один файл на модуль або на сторінку. Назви тестів — реченням про поведінку, а
не про назву функції: коли тест упаде, у звіті має бути видно, що саме
зламалось для користувача.
